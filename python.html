01 / PYTHON

程式是食譜：先寫清楚輸入與輸出

把Python想成照步驟工作的助手。它不會猜「差不多」是什麼，而是執行你明確寫出的規則。先讀程式、猜輸出，再執行核對。下列是Python 3程式，print把結果顯示出來；#之後是註解，不會執行。

先猜輸出，再執行

print("開始整理訂單")
print(120 + 80)  # 加總金額
核對預期結果
開始整理訂單 200

換你修改與解釋

把兩筆金額改成150與90，先口算再跑。

教回去：參考解析

輸出總額240。說清楚輸入是兩筆金額，運算是加法，輸出是總額。

02 / PYTHON

變數與型別：標籤貼在值上

變數比較像指向物件的名稱，不是永久固定型別的盒子。整數int、浮點數float、字串str、布林bool有不同操作。=是指定，==是比較；字串數字不會自動變金額。浮點數不適合不加考慮地當精確金額，實務可用整數最小貨幣單位或Decimal。

先猜輸出，再執行

price = 120
quantity = int("3")
total = price * quantity
print(total, total >= 300)
print("3" * 2)
核對預期結果
360 True 33

換你修改與解釋

為何"3" * 2不是6？

教回去：參考解析

字串乘整數是重複；int("3") * 2才是整數6。先說型別，再談運算。

03 / PYTHON

字串與清理：先整理標籤再比較

使用者常多打一個空白或混用大小寫。strip去掉頭尾空白，lower轉小寫；不是把中間所有空白都刪除。f-string把變數放入文字，能讓輸出清楚。

先猜輸出，再執行

status = " Paid ".strip().lower()
print(status == "paid")
print(f"付款狀態：{status}")
核對預期結果
True 付款狀態：paid

換你修改與解釋

若內容是"Not Paid"，清理後會變paid嗎？

教回去：參考解析

不會，會變not paid。字串清理不等於理解業務狀態，應明確定義可接受值。

04 / PYTHON

清單與字典：一列貨物與一張訂單

list保留順序，索引從0開始；dict用鍵找值。清單切片右邊界不包含。找不存在的索引會IndexError，找不存在的字典鍵會KeyError；get可提供預設值，但不要用預設值掩蓋必填欄位缺失。

先猜輸出，再執行

prices = [100, 200, 300]
order = {"id": "A01", "amount": 200}
print(prices[0], prices[1:3])
print(order["amount"], order.get("coupon", "無"))
核對預期結果
100 [200, 300] 200 無

換你修改與解釋

把prices[0]改成prices[3]會怎樣？

教回去：參考解析

會IndexError。三筆資料的有效索引是0、1、2；最後一筆也可用prices[-1]。

05 / PYTHON

if：把判斷寫成清楚的分岔

if、elif、else像分類櫃檯。縮排表示哪些指令屬於同一區塊，建議每層4個空白。先想邊界：滿300免運，300本身應該進哪邊？

先猜輸出，再執行

amount = 300
if amount >= 300:
    shipping = 0
else:
    shipping = 60
print(shipping)
核對預期結果
0

換你修改與解釋

分別用299、300、301測試。

教回去：參考解析

運費應為60、0、0。把>=寫成>會讓剛好300的訂單被錯收運費。

06 / PYTHON

for：逐筆做事，再累積結果

for像依序拿起每張訂單。累計器要在迴圈外先設好；若每次都重設0，就只留下最後一筆。range(3)產生0、1、2。先把三圈的total寫在紙上。

先猜輸出，再執行

amounts = [100, 250, 80]
total = 0
for amount in amounts:
    total += amount
print(total)
print([x for x in amounts if x >= 100])
核對預期結果
430 [100, 250]

換你修改與解釋

把total = 0移到for裡會發生什麼？

教回去：參考解析

每圈都歸零，最後只剩80。清單推導式則是在建立符合條件的新清單。

07 / PYTHON

函式：把規則裝成可重用的小工具

def定義函式，參數是輸入，return交回結果；print只是顯示。沒有return的函式會回傳None。先讓函式只處理一件事，再用不同輸入檢查。型別註記提供說明，不會自動替你完成所有輸入驗證。

先猜輸出，再執行

def shipping(amount):
    if amount < 0:
        raise ValueError("金額不可為負")
    return 0 if amount >= 300 else 60

print(shipping(299), shipping(300))
核對預期結果
60 0

換你修改與解釋

若只print運費、不return，拿函式結果相加會如何？

教回去：參考解析

得到None而不是數字，可能觸發TypeError。運算需要回傳值，顯示結果才用print。

08 / PYTHON

共享物件：兩張標籤不等於兩份資料

b = a不會複製清單，兩個名稱指向同一物件。copy建立淺複本，對只有數字的清單夠用；若裡面還有巢狀清單或字典，內層仍可能共用。

先猜輸出，再執行

a = [100, 200]
b = a
b.append(300)
c = a.copy()
c.append(400)
print(a)
print(c)
核對預期結果
[100, 200, 300] [100, 200, 300, 400]

換你修改與解釋

為何改b也改到a，改c卻沒有？

教回去：參考解析

a與b是同一清單；c是新的外層清單。別把指派誤認成完整複製。

09 / PYTHON

錯誤訊息：把它當定位線索

從traceback最後一行讀錯誤種類，再找自己的程式行號。SyntaxError常是語法，NameError是名稱不存在，TypeError是型別操作不合，ValueError常是值不符合要求。只攔能處理的錯誤，不要用空白except吞掉全部問題。

先猜輸出，再執行

raw = "abc"
try:
    amount = int(raw)
except ValueError:
    print("請輸入整數金額")
核對預期結果
請輸入整數金額

換你修改與解釋

把錯誤金額一律改成0，有什麼風險？

教回去：參考解析

可能把無效資料偽裝成真實零元訂單。應記錄、拒絕或依明確規則處理。

10 / PYTHON

CSV：讀檔不是用逗號硬切

csv模組會處理引號等格式，比自己split(",")可靠。這裡用StringIO模擬檔案，不需下載資料。實際檔案可用with open("orders.csv", newline="", encoding="utf-8-sig") as f，再交給DictReader；with會管理關閉。相對路徑以工作目錄為基準。

先猜輸出，再執行

import csv
from io import StringIO

text = "id,amount\nA01,120\nA02,80\n"
orders = list(csv.DictReader(StringIO(text)))
print(sum(int(row["amount"]) for row in orders))
核對預期結果
200

換你修改與解釋

為什麼讀進來的amount還要轉int？

教回去：參考解析

CSV欄位通常是文字。必須先定義型別與無效值規則，再計算金額。

11 / PYTHON

pandas：把資料表當有欄名的工作台

此節需要pandas。DataFrame是有列與欄的表格，先看shape、dtypes、head及缺失值，再做統計。下例明確把金額轉數字，無法轉換者變缺失，保留原欄並排除無效金額後計算。這是示範規則，不能把所有缺失一律丟掉。

先猜輸出，再執行

import pandas as pd

df = pd.DataFrame({"region": ["北", "南", "北"],
                   "amount": ["100", "200", "錯誤"]})
df["amount_num"] = pd.to_numeric(df["amount"], errors="coerce")
valid = df.dropna(subset=["amount_num"])
print(int(df["amount_num"].isna().sum()))
print(int(valid["amount_num"].sum()))
核對預期結果
1 300

換你修改與解釋

如果錯誤金額集中在某地區，直接刪除會怎樣？

教回去：參考解析

可能造成代表性偏差。應保留無效筆數、追查來源並評估統計與模型影響。

12 / PYTHON

篩選與分組：先問業務問題

pandas的布林條件選出資料；多條件使用&或|並各自加括號，不使用Python單值的and/or。groupby像按區域把單據分成幾疊再加總。筆數相同不代表金額相同，平均也可能掩蓋分布。

先猜輸出，再執行

import pandas as pd

df = pd.DataFrame({"region": ["北", "南", "北"],
                   "amount": [100, 200, 300]})
selected = df.loc[(df["amount"] >= 200) & (df["region"] == "北")]
print(selected["amount"].tolist())
print(df.groupby("region")["amount"].sum().to_dict())
核對預期結果
[300] 北區加總400、南區加總200（字典顯示順序不影響結果）

換你修改與解釋

把&改成and為什麼可能出錯？

教回去：參考解析

Series包含多個真假值，不能直接當成一個布林值；&在這裡逐列合併條件。

13 / PYTHON

測試：用小例子確認你寫的是原本的規則

assert可讓開發時的錯誤假設立即顯現。測一般值、邊界和無效值，而不是只測漂亮例子。assert不應取代正式輸入驗證，因為最佳化執行可停用assert。

先猜輸出，再執行

def shipping(amount):
    if amount < 0:
        raise ValueError("金額不可為負")
    return 0 if amount >= 300 else 60

assert shipping(299) == 60
assert shipping(300) == 0
try:
    shipping(-1)
except ValueError:
    print("邊界與無效值測試通過")
核對預期結果
邊界與無效值測試通過

換你修改與解釋

如果只測100和500，會漏掉哪種錯誤？

教回去：參考解析

可能漏掉300這個邊界用>或>=的差別。測試應來自規則與風險，而非照抄實作。

14 / PYTHON

機器學習：fit是學規則，predict是交答案

頁首下載的完整程式用合成分類資料示範Pipeline：先切分訓練與測試，只用訓練集學補值、縮放與分類器，再在測試集預測。這對應L23301與L23303。它是流程練習，不是可直接上線的客服模型；真實時間序列或同人多筆資料需要相應切分。

先猜輸出，再執行

from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model = make_pipeline(
    SimpleImputer(strategy="median"),
    StandardScaler(),
    LogisticRegression(max_iter=1000)
)
# X_train等資料由頁首完整下載程式建立
# model.fit(X_train, y_train)
# predictions = model.predict(X_test)
核對預期結果
本片段只建立模型，沒有輸出；請執行完整python-ml.py查看結果。

換你修改與解釋

為何不能先用全資料算平均和縮放，再切測試集？

教回去：參考解析

測試資料資訊會進入學習流程，造成洩漏。Pipeline配合正確切分，讓前處理跟著訓練資料學習。

15 / PYTHON

讀懂評估：分數高，還要知道錯在哪裡

混淆矩陣不是神祕圖：TP是正例猜對，FN是正例漏掉，FP是負例誤報，TN是負例猜對。下面手算Recall，不需要外部套件。總分之外也要看分組、樣本量和錯誤成本，連回L23402。

先猜輸出，再執行

tp, fn, fp, tn = 40, 10, 10, 40
recall = tp / (tp + fn) if tp + fn else None
accuracy = (tp + tn) / (tp + fn + fp + tn)
print(recall, accuracy)
核對預期結果
0.8 0.8

換你修改與解釋

若沒有任何真正正例，Recall應填0還是100%？

教回去：參考解析

分母為0，沒有可評估的正例，應標示未定義與原因；不要假裝是完美或完全失敗。

16 / PYTHON

費曼總練習：不用術語教完一個小專案

把工作分成輸入、檢查、處理、輸出、驗證五步。用訂單例子說清：金額從哪來、文字怎麼轉數字、錯誤如何處理、滿額運費怎麼算、怎麼證明沒算錯。再換成客服案件試一次；說不清楚的步驟，就是需要回讀的地方。

先猜輸出，再執行

orders = [{"id": "A01", "amount": 120},
          {"id": "A02", "amount": 350}]
for order in orders:
    fee = 0 if order["amount"] >= 300 else 60
    print(order["id"], order["amount"] + fee)
核對預期結果
A01 180 A02 350

換你修改與解釋

加入一筆金額為-20的訂單，你要把檢查放在哪裡？

教回去：參考解析

在套用運費與輸出之前先驗證金額，拒絕無效值或交由明確流程處理；不要讓負值悄悄進入報表。
